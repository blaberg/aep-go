# AEP-Go Example Service

This example demonstrates how to use the AEP-Go library to build a gRPC service that follows AEP standards. The service implements:

- Resource path parsing and creation, with code generated by `protoc-gen-go-aep`
- Resources with multiple patterns
- Resource ID generation and validation
- Pagination with token-based validation

## Service Overview

The example implements a simple Book Service. A book has one of two patterns:

- `authors/{author_id}/books/{book_id}`: a book written by an author, which only that author can change.
- `books/{book_id}`: a top-level book without a single author, such as an anthology, which only an admin can change.

The service has the following operations:
- `CreateBook`: Creates a book written by an author, or a top-level book if no parent is given, with an optional or auto-generated ID
- `GetBook`: Retrieves a book by its resource path
- `ListBooks`: Lists the books of an author, or the top-level books if no parent is given, with pagination
- `UpdateBook`: Updates a book, if the caller may change it
- `DeleteBook`: Deletes a book, if the caller may change it

The caller is read from the `x-user` request metadata. This is a stand-in for real authentication, to keep the example short.

## Multiple Patterns

The generated `ParseBookResourcePath` parses a path with any of the book's patterns, and `Pattern` returns the pattern it has. `authorize` in `service.go` switches on it to decide who may change a book:

```go
switch path.Pattern() {
case booksv1.AuthorBookPattern:
	if caller != path.GetAuthorId() {
		return status.Errorf(codes.PermissionDenied, "only author %q can change this book", path.GetAuthorId())
	}
case booksv1.BookPattern:
	if caller != "admin" {
		return status.Error(codes.PermissionDenied, "only admins can change top-level books")
	}
}
```

To create a path, there is a generated constructor for each pattern: `NewAuthorBookResourcePath(authorId, bookId)` and `NewBookResourcePath(bookId)`.
